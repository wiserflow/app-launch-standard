# Support and communication (SUP)

| ID | L | Requirement |
| --- | --- | --- |
| SUP-01 | 1 | Visible support channel in the app with stated response time (a plain monitored mailbox counts) |
| SUP-02 | 1 | Help center covering the top 10 questions (Starlight / Fumadocs / in-app) |
| SUP-03 | 2 | Public changelog + "what's new" indicator in the app |
| SUP-04 | 2 | In-app notifications (bell) with per-type preferences |
| SUP-05 | 2 | Feedback widget with triage |
| SUP-06 | 2 | Omnichannel inbox (Chatwoot) if support runs on chat/WhatsApp |
| SUP-07 | 3 | Public idea board with votes (Fider) |
| SUP-08 | 1 | All channels (widget, WhatsApp, email) land in **one** inbox (a single shared mailbox counts when there is one owner; a tool such as Chatwoot when several channels); out-of-hours auto-reply states business hours |
| SUP-09 | 1 | Escalation path support → engineering (ticket ↔ issue link in whatever tracker is used, e.g. GitHub issues) with severity definitions (a one-line "what is urgent" is enough for a single owner) |
| SUP-10 | 1 | Support can see an account's context without the password; any impersonation audited (→ ADM-04) |
| SUP-11 | 2 | Macros for top-20 issues; tag taxonomy reviewed monthly; CSAT after resolution; first-response and resolution time on a dashboard |
| SUP-12 | 2 | Bot/AI deflection always offers a human handoff |
| SUP-13 | 3 | SLA tiers per plan, support on-call rotation, status-page integration; help-center search analytics drive the docs backlog |

Reference: [Chatwoot user guide](https://www.chatwoot.com/hc/user-guide/en).
