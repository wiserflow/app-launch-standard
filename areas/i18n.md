# Internationalization and localization (I18N)

Even single-locale apps do I18N-01..05: they are cheap at the start and expensive to retrofit. I18N-06 is n/a when Kickoff says one locale, but its mechanism still applies once a second locale appears. A catalog library is not required for one locale: centralized strings in one module/file, keyed and never inline, satisfy I18N-01 and I18N-05 (plurals/interpolation helper still required).

| ID | L | Requirement |
| --- | --- | --- |
| I18N-01 | 1 | No hardcoded user-facing string: everything through a message catalog or centralized keyed strings, even with one locale; proof: lint rule or grep over UI code finds no literals |
| I18N-02 | 1 | Timestamps stored UTC (`timestamptz`), no server-local time. Storage (always testable) = `timestamptz`/UTC. Rendering = user's (team accounts: tenant's) IANA time zone; a fixed single zone is acceptable when Kickoff says one country/zone, if configured in one place |
| I18N-03 | 1 | Money as integer minor units + ISO 4217 code, never float; formatted with `Intl.NumberFormat` |
| I18N-04 | 1 | Dates/numbers via `Intl` with explicit locale |
| I18N-05 | 1 | Plurals and interpolation via ICU MessageFormat or equivalent helper; no string concatenation (→ I18N-01) |
| I18N-06 | 1 | Emails, notifications and server errors localized by the **user's** locale, not the request's (n/a with one locale, see intro) |
| I18N-07 | 2 | Pseudo-locale build in CI/e2e catches truncation and unwrapped strings; missing keys fail CI |
| I18N-08 | 2 | Locale negotiation (user setting → `Accept-Language` → default) persisted per user; `hreflang` on public pages |
| I18N-09 | 2 | Country formats (tax ids, postal codes, phones) validated behind a locale-aware layer |
| I18N-10 | 3 | Translation management workflow; RTL readiness (CSS logical properties); multi-currency pricing with tax rules |

References: [W3C i18n quick tips](https://www.w3.org/International/quicktips/) · [Pseudo-localization (Microsoft)](https://learn.microsoft.com/en-us/globalization/methodology/pseudolocalization) · [ICU message syntax](https://formatjs.github.io/docs/core-concepts/icu-syntax/).
