# Product discovery and requirements (PRD)

Spine: superpowers `brainstorming` → `writing-plans`. Add one spec skill (`to-spec`) — spec-kit and BMAD duplicate it and write many files into the repo.

| ID | L | Requirement |
| --- | --- | --- |
| PRD-01 | 1 | One-page PRD in `PRODUCT.md`/`docs/`: problem, target user (JTBD), success metric **with a number** (non-goals → PRD-04) |
| PRD-02 | 1 | Problem validated with ≥5 real target users or paying-intent evidence (waitlist, pre-sale, LOI). Brownfield product already live: recorded feedback from its real users counts (who, date, what) |
| PRD-03 | 1 | Every launch-scope story has testable acceptance criteria (Given/When/Then or EARS) |
| PRD-04 | 1 | Launch scope frozen, with an explicit "not in v1" list |
| PRD-05 | 1 | Pricing hypothesis written (plans, limits, price) and linked to BIL-01; free product with no billing: a one-line monetization stance (free now, how/when it may charge) is enough and the BIL-01 link applies once BIL applies |
| PRD-06 | 1 | Spec → plan → tasks live in the repo and are linked from PRs (or from commit messages/the change log if the repo has no PR workflow) |
| PRD-07 | 2 | Outcome roadmap (now / next / later) published |
| PRD-08 | 2 | Feedback intake feeds a triaged backlog; each shipped feature maps to a tracked metric (ANL) |
| PRD-09 | 3 | Spec-vs-implementation drift reviewed quarterly; enterprise asks (SSO, audit, SLA) captured as specs |

References: [github/spec-kit spec-driven.md](https://github.com/github/spec-kit/blob/main/spec-driven.md) · [Kiro specs (EARS)](https://kiro.dev/docs/specs/) · Shape Up (basecamp.com/shapeup).
